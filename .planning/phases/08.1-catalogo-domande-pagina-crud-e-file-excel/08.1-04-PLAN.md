## Phase Goal

**Come** admin che tara il catalogo, **voglio** curare domande, opzioni ed effetti dal pannello e da un file Excel, **così che** cambiare una domanda non richieda un deploy.

<objective>
Secondo livello del master-detail (D-24): scelta una domanda, sotto compaiono le sue opzioni,
curabili con il form di D-38 e disattivabili con un toggle (D-27). Il rifiuto D-28 arriva come
toast col testo del backend, verbatim (UI-SPEC §D.6). Le domande `stepper`/`numero` saltano
questo livello (D-35): la loro opzione implicita esiste ma non si mostra.

Purpose: completa la meta' "cosa succede se scelgo questa risposta" della pagina; il piano 06
aggiunge sotto il terzo livello, gli effetti.
Output: `pages/admin/domande/OpzioniSezione.tsx` e lo stato di selezione in `DomandePage.tsx`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin → `PATCH /admin/domande/opzioni/{id}` | il toggle puo' spegnere un'opzione in uso |
| URL immagine scritto dall'admin → `<img src>` nel pannello | contenuto esterno caricato nel browser dell'admin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08.1-30 | Tampering | disattivazione di un'opzione in uso dalla UI | mitigate | il rifiuto e' server-side (piano 01, `verifica_dipendenze_opzione`); la UI mostra il `detail` e non ha un percorso alternativo |
| T-08.1-31 | Tampering | URL immagine con schema `javascript:` | accept | un `src` di `<img>` non esegue script nei browser moderni; campo gia' `max_length=500` lato server; l'autore e' un admin autenticato |
| T-08.1-32 | Information Disclosure | caricamento di un'immagine esterna rivela l'IP dell'admin al dominio dell'URL | accept | stessa esposizione che l'immagine ha gia' nel wizard pubblico; nessun dato sensibile |
| T-08.1-SC | Tampering | installazioni npm | mitigate | nessun pacchetto nuovo |
</threat_model>
