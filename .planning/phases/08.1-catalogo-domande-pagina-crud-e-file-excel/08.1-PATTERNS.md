## Pattern Assignments

### `backend/alembic/versions/0020_attiva_updated_at_catalogo.py` (migration, batch)

**Analog:** `backend/alembic/versions/0019_updated_at_curatela.py` (verbatim pattern, all 100 lines read)

Two distinct techniques in the same file, confirmed by reading `0019` in full and
`models/domanda.py`'s existing `server_default="1"` boolean columns (`Domanda.attiva`
line 83-85, `EffettoOpzione.attivo` line 161-163, `DerivazioneRisposta.attiva` line
246-248 — all plain `add_column`-safe, no batch dance needed):

**Boolean columns — single-step, SQLite accepts a string-literal default directly:**
```python
op.add_column("opzione_domanda", sa.Column("attiva", sa.Boolean(), nullable=False, server_default="1"))
op.add_column("attesa_immobile", sa.Column("attiva", sa.Boolean(), nullable=False, server_default="1"))
```

**`updated_at` on all five catalog tables — three-step dance, copy verbatim from `0019` lines 75-86:**
```python
# Source: backend/alembic/versions/0019_updated_at_curatela.py:70-86
adesso = datetime.now(timezone.utc).replace(tzinfo=None)

_TABELLE = ("domanda", "opzione_domanda", "effetto_opzione", "attesa_immobile", "derivazione_risposta")

for tabella in _TABELLE:
    op.add_column(tabella, sa.Column("updated_at", sa.DateTime(), nullable=True))
    op.execute(
        sa.text(f"UPDATE {tabella} SET updated_at = :adesso").bindparams(adesso=adesso)
    )
    with op.batch_alter_table(tabella) as batch:
        batch.alter_column(
            "updated_at",
            existing_type=sa.DateTime(),
            nullable=False,
            server_default=sa.func.now(),
        )
```

**Why the three-step dance is mandatory for `updated_at` but not for `attiva`:**
`0019`'s incident (documented in its own docstring, lines 43-47) was
`ALTER TABLE ... ADD COLUMN ... DEFAULT CURRENT_TIMESTAMP` failing on SQLite with
`Cannot add a column with non-constant default` — `server_default=func.now()`
compiles to a non-constant expression, while `server_default="1"` is a constant
string literal SQLite's `ADD COLUMN` accepts directly. Do not "simplify" the boolean
columns into the batch pattern — it is unneeded work, not a safety net.

**`down_revision`:** confirmed `0019` is the current head (`ls alembic/versions` sorted,
no revision after `0019`) — this migration's `revision = '0020'`, `down_revision = '0019'`.

**Verification requirement (from 0019's own incident, inherited):** run
`backend/.venv/Scripts/python.exe -m alembic upgrade head` against the real
`backend/dev.db`, not just the test suite — `test_admin_domande.py`'s fixture builds
schema via `Base.metadata.create_all`, which tells you nothing about migration
correctness (confirmed at its own `client` fixture, line 43).

**`downgrade()`:** mirror `0019`'s reversed-order `batch_alter_table` drop for the
three `updated_at` columns it added via batch, plus plain `op.drop_column` for the
two `attiva` columns it added via plain `add_column`.

### `backend/app/services/domande_dipendenze.py` (NEW service, request-response)

**Analog:** `backend/app/services/effetti.py::valida_effetto`/`EffettoNonValido`

**Concrete query shape** (from RESEARCH.md Pitfall 4, verified field names against

```python
from sqlalchemy import and_, or_
from app.models.domanda import Domanda, DerivazioneRisposta, OpzioneDomanda

def verifica_dipendenze_opzione(db: Session, opzione: OpzioneDomanda) -> str | None:
    """Ritorna il motivo del rifiuto (D-28), o None se disattivabile."""
    if opzione.is_default:
        domanda = db.get(Domanda, opzione.domanda_code)
        return f"e' la risposta predefinita di {domanda.testo}"

    derivazione = db.query(DerivazioneRisposta).filter(
        DerivazioneRisposta.attiva.is_(True),
        or_(
            and_(DerivazioneRisposta.domanda_code == opzione.domanda_code,
                 DerivazioneRisposta.quando_opzione_code == opzione.code),
            and_(DerivazioneRisposta.domanda_code == opzione.domanda_code,
                 DerivazioneRisposta.opzione_code == opzione.code),
            and_(DerivazioneRisposta.da_domanda_code == opzione.domanda_code,
                 DerivazioneRisposta.da_opzione_code == opzione.code),
        ),
    ).first()
    if derivazione is not None:
        return "la usa una derivazione di risposta attiva"  # D-28: nominare la derivazione concreta

    domanda_dipendente = db.query(Domanda).filter(
        Domanda.attiva.is_(True),
        Domanda.visibile_se_domanda_code == opzione.domanda_code,
        Domanda.visibile_se_opzione_code == opzione.code,
    ).first()
    if domanda_dipendente is not None:
        return f"e' la condizione di visibilita' di {domanda_dipendente.testo}"

    return None
```
Called from **both** `routers/admin/domande.py::modifica_opzione` (raise

resolver (append `ScartoRowOut(motivo=motivo)` instead — never blocks the whole import,
per UI-SPEC §B).

### `backend/app/services/export_excel/domande.py` (NEW, file-I/O export)

**Analog:** `backend/app/services/export_excel/parametri.py` (full file read, 192 lines) —
same shape, five `_righe_*(db)` functions each returning `list[dict]`, one
`build_workbook_domande(db) -> tuple[bytes, int]` that calls `scrivi_foglio_dati` five
times and sums the row counts.

**Structural template (adapt table/column names only):**
```python
# Source: backend/app/services/export_excel/parametri.py:1-26 (module docstring shape),
# :62-73 (one _righe_* function), :156-191 (build_workbook_* orchestrator)
from app.services.export_excel.workbook import nuovo_workbook, scrivi_foglio_dati, serializza

COLONNE_DOMANDE = ["id", "testo", "help", "tipo_controllo", "gruppo", "ordine",
                    "tier_minimo", "attributo_code", "obbligatoria",
                    "visibile_se_domanda_code", "visibile_se_opzione_code", "attiva"]
# id column holds Domanda.code (string PK) — see import_excel counterpart's
# `id_numerico=False` note below.

def _righe_domande(db: Session) -> list[dict]:
    rows = db.query(Domanda).order_by(Domanda.ordine, Domanda.code).all()
    return [{"id": r.code, "testo": r.testo, ..., "attiva": r.attiva} for r in rows]

# ... _righe_opzioni, _righe_effetti (context columns domanda_code/opzione_code
# read-only, mirroring `opzione_etichetta` in _righe_forfait_arredo:135-153),
# _righe_attese, _righe_derivazioni

def build_workbook_domande(db: Session) -> tuple[bytes, int]:
    wb = nuovo_workbook()  # con_margine never True for this catalog — no coefficiente_impresa
    n_righe = 0
    n_righe += scrivi_foglio_dati(wb, nome="domande", colonne=COLONNE_DOMANDE, righe=_righe_domande(db))
    # ... four more scrivi_foglio_dati calls, one per sheet
    return serializza(wb), n_righe
```
No `con_margine` branch anywhere in this module — unlike `parametri.py`, this catalog
never contains `coefficiente_impresa` (CLAUDE.md rule #1), so `nuovo_workbook()` is
always called with defaults and there is never an `AVVISO` sheet.
