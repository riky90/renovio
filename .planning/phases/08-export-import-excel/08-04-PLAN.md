<objective>
CUR-03. I parametri del motore — moltiplicatori, base €/m² e IVA, extra, coefficienti Pro,
forfait arredo — escono in un solo file a cinque fogli. **Di default il file non e'
sensibile**: nessuna colonna di margine, quindi nessun avviso necessario e nessun rischio
se l'allegato gira. Il `coefficiente_impresa` esce solo se qualcuno lo chiede
esplicitamente, e allora il file e' marcato nel nome, si apre su un foglio di avviso ed e'
registrato a nome di chi lo ha preso.

Purpose: e' la traduzione nel mondo dei file della regola di dominio #1 di `CLAUDE.md`. La
regola non deve dipendere da chi apre l'allegato: deve dipendere dal fatto che il segreto
nel file non ci sia.
Output: `GET /admin/coefficienti/export.xlsx` (+ `?margine=true`), split-button con
conferma in pagina, test che legge il workbook e verifica l'assenza della colonna.

Chiude anche il punto aperto "nessun CRUD admin su `forfait_arredo`": i 18 forfait, oggi
curabili solo dal seed, diventano un foglio (D-08).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `GET /admin/coefficienti/export.xlsx[?margine=true]` | il ruolo dichiarato dal client non conta: il gate e' `require_admin` server-side |
| workbook con margine → fuori dall'applicazione | e' il confine di riservatezza di questa fase: superato quello, nessun controllo tecnico protegge piu' il coefficiente |
| riga `export_log` | l'unico modo di rispondere a "chi si e' portato via il coefficiente impresa" |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-30 | Information Disclosure | export di default che include per sbaglio la colonna di margine | mitigate | la colonna si **aggiunge** solo nel ramo `con_margine=True`, non si filtra a valle; `test_export_default_non_contiene_coefficiente_impresa` apre il workbook e controlla gli header di tutti i fogli |
| T-08-31 | Elevation of Privilege | endpoint del margine raggiungibile da un consulente | mitigate | `Depends(require_admin)` sulla funzione di route (non solo sul router); `test_export_margine_vietato_al_consulente` verifica 403 su entrambe le varianti |
| T-08-32 | Information Disclosure | nome file o foglio AVVISO rimossi, il file sensibile diventa indistinguibile | mitigate | il nome file e il foglio `AVVISO` sono generati server-side da `build_filename`/`nuovo_workbook`, non dal client; due acceptance criteria li verificano leggendo il file |
| T-08-33 | Repudiation | download del margine non attribuibile | mitigate | `ExportLog` con `user_id` da `require_admin` e `include_margine=True`; `test_export_log_distingue_le_due_varianti` conta le righe |
| T-08-34 | Information Disclosure | risposta con il margine finita in una cache condivisa o in un proxy | mitigate | aggiungere `Cache-Control: no-store` agli header della `StreamingResponse` della variante con margine (e, per uniformita', di entrambe): un `.xlsx` con il coefficiente non deve mai essere ri-servito da una cache |
| T-08-35 | Spoofing | conferma del dialog attivata per sbaglio da Invio | mitigate | `autoFocus` sull'`AlertDialogCancel` (UI-SPEC §B), verificato da acceptance criterion |
| T-08-SC | Tampering | installazioni npm/pip | mitigate | nessun pacchetto nuovo: `dropdown-menu` e `alert-dialog` sono gia' in `frontend/src/components/ui/`, `openpyxl` e' gia' nel backend |
</threat_model>
