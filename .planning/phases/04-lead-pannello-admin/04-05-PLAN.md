## Phase Goal

**As a** admin, **I want to** caricare in blocco un listino da Excel per una città (nuova o esistente) con anteprima del diff prima di applicare, **so that** posso onboardare/aggiornare i prezzi di una città senza data-entry manuale e senza rischio di azzerare i dati esistenti (ADM-01 bulk, ROADMAP Success Criterion #3, D-13/D-18/D-19/D-20/D-24).

> Slice verticale (livello server): consegna il flusso upload/diff/confirm con destinazione (listino esistente o nuova città) come API testabili. Il piano 04-08 aggiunge la UI dropzone/diff con l'entry-point "Nuova città".

<objective>
Costruire il flusso Excel a due passi lato server (D-18): `POST /admin/upload-listino/preview` (parse + diff, NIENTE scritture) e `POST /admin/upload-listino/confirm` (upsert idempotente per chiave naturale, mai distruttivo), con un parametro di **destinazione**: `listino_id` esistente OPPURE dati per una **nuova città** (nome città + flag nuovo listino) → il confirm crea `Listino` + voci + `ComuneListino` (D-13). Estrarre le funzioni di classificazione riga dallo script Phase 3 in un modulo condiviso hardened per input non fidato (Pitfall 1).

Purpose: ADM-01 (caricamento bulk + onboarding città nuova).
Output: promozione openpyxl a runtime + pin python-multipart + modulo parsing condiviso + upload service (2 rami) + schema diff + router + test.
</objective>

| Boundary | Description |
|----------|-------------|
| client→POST /admin/upload-listino/* (multipart) | file .xlsx non fidato ed elaborato lato server |
| parsed rows→upsert DB | dati non validati che pilotano prezzi/coefficienti |

| npm/pip installs | supply chain (openpyxl scope-change, python-multipart pin) |
