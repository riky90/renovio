<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API (pdf-pro) | Free/anonimo può tentare il download del PDF Pro bypassando la UI |
| client → API (ownership) | Un Pro può tentare il PDF di una stima altrui (IDOR) |
| server → PDF (render) | Rischio di stampare prezzi/coefficienti impresa nel template |
| codice ↔ codice (drift) | PDF e JSON potrebbero divergere se ricalcolano con logiche separate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-08 | Elevation of Privilege | GET pdf-pro | mitigate | Stesso `Depends(require_pro)` del JSON (D-08); parità di autorizzazione tra JSON e PDF |
| T-03-06b | Information Disclosure (IDOR) | GET pdf-pro | mitigate | Ownership-filter `id + user_id` → 404 (non 403), come `scarica_pdf_stima` |
| T-03-01d | Information Disclosure | pdf_stima_pro.html, render_pro | mitigate | Template rende solo campi cliente del `DettaglioProResult` (già anti-leak); test anti-leak su bytes/HTML; grep-gate su template |
| T-03-09 | Tampering (drift) | pdf-pro vs dettaglio-pro | mitigate | Entrambi delegano allo STESSO `DettaglioProService.compute()`/`_compute_dettaglio()` con argomenti identici (incluse risposte_pro_json); test di parità numerica (Pitfall 2) |
</threat_model>
