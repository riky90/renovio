# Phase 3 — UI Design Contract

> Visual and interaction contract for Pro & dettaglio sottocategorie (paywall gate, targeted quantity questions, Pro sub-category detail view, upgrade/payment-stub flow, PDF Pro). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **Language of all UI copy: Italian.** Design system already exists from Phase 1 (`01-UI-SPEC.md`) and Phase 2 (`02-UI-SPEC.md`) — this document **extends** both, it does not reinvent them. All spacing, typography and color tokens carry over unchanged unless a delta is stated below. Existing components `CategoryCard`, `TotalCard`, `FallbackDisclaimer`, `SoftWallCta`, `PdfDownloadButton` are reused/modified, not replaced.

## Spacing Scale

Unchanged from Phase 1/2 — 8-point scale, reused as-is.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, voce row internal padding |
| sm | 8px | Compact spacing (accordion trigger padding, quantity input adornment) |
| md | 16px | Default gap between form fields, inside cards, between accordion items |
| lg | 24px | Card inner padding, gap between sottocategoria accordions |
| xl | 32px | Section breaks (targeted questions → detail, detail → CTA cluster) |
| 2xl | 48px | Page top/bottom padding on desktop |
| 3xl | 64px | Not used in Phase 3 screens |

**Exceptions (carried over):** interactive touch targets (accordion triggers, quantity inputs, buttons) have a minimum height of 44px. New: the per-voce row itself is not a tap target and may be as compact as 32px height — only the accordion trigger (sottocategoria header) and any editable quantity field need the 44px minimum.

## Typography

Unchanged from Phase 1/2 — Inter, exactly 2 weights (400 regular, 600 semibold), exactly 4 roles.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.3 |
| Display | 30px | 600 | 1.2 |

- **Body** — voce description text, UM/quantity helper copy, targeted-question helper text, upgrade page fine print.
- **Label** — sottocategoria accordion trigger title, voce row primary text, field labels on targeted questions, button text.
- **Heading** — screen/section titles ("Dettaglio Pro", "Passa a Pro", sottocategoria group header inside catalog family screens if used as a section title rather than accordion).
- **Display** — not introduced net-new; Pro detail per-voce/per-sottocategoria ranges use **Label** size (14px) with tabular figures, never Display — Display stays reserved for the single overall total (Free) per Phase 1, keeping visual hierarchy: the Pro detail is supporting evidence, not a competing hero number. If a sottocategoria subtotal is shown, it uses **Heading** size at most.

All money figures keep `tabular-nums`. Quantity figures (voce rows, targeted-question inputs) also use `tabular-nums` for column alignment.

## Color

Unchanged from Phase 1/2 — single accent, 60/30/10 split, base **Slate**, accent **blue-600** (`#2563EB`). No new hue introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8FAFC` (slate-50) | Page background on all Phase 3 screens |
| Secondary (30%) | `#FFFFFF` on `#E2E8F0` borders (slate-200) | Category cards, accordion panels, upgrade card, targeted-question card |
| Accent (10%) | `#2563EB` (blue-600) | See reserved list below |
| Destructive | `#DC2626` (red-600) | Validation/payment-stub failure messaging only |

**Text colors (neutral, not counted in 60/30/10):** primary `#0F172A` (slate-900), secondary/muted `#64748B` (slate-500), on-accent `#FFFFFF`.

**Accent (`#2563EB`) reserved exclusively for, in Phase 3 — additions to the Phase 1/2 list:**
1. Primary CTA "Passa a Pro" now **navigates** (instead of the Phase 1 soft-wall toast) to the upgrade screen §B — same accent button, same placement, new behavior.
2. Primary CTA on the upgrade screen: "Attiva Pro" (payment-stub confirm button).
3. The **Pro badge** (small accent-filled `badge`, `bg-primary text-primary-foreground`) marking the account as Pro in the header/account menu once active — the only accent use inside the account dropdown besides the existing focus ring.
4. Accordion trigger chevron/active-state accent tint when a sottocategoria is expanded (subtle, e.g. `text-primary` on the chevron icon only — not the whole row background).

Accent is **never** applied to: individual voce rows, the lock/paywall teaser card, more than one CTA per screen (upgrade screen has exactly one primary accent CTA), or the targeted-question inputs (neutral `input`/`input-group` styling, focus ring only per existing global rule).

**Locked/paywall teaser tone (net-new semantic use, no new hue):** uses the **neutral slate** treatment, not amber and not destructive — a locked sottocategoria is not an error or a warning, it's a value proposition. Lock icon (`Lock` from lucide) in `text-muted-foreground`, teaser panel `bg-muted` (slate-100) with a slate-200 border, blurred/redacted sample row (see §C.3) plus the accent "Passa a Pro" link — this is the same accent CTA reused, not a new color.

**Amber info tone** (unchanged: `#FFFBEB` bg / `#FCD34D` border / `#B45309` text) reused for: the fallback-listino disclaimer (unchanged, carried from Phase 1) and, new in Phase 3, the **targeted-question helper note** explaining defaults are used when the user skips a question (informational, not an error).

**Destructive (`#DC2626`) reserved for:** targeted-question numeric validation (negative/absurd counts), payment-stub failure state (simulated failure path, if the executor implements one), and the PDF Pro generation error (reuses the exact Phase 2 `PdfDownloadButton` inline error pattern).

**Contrast:** all pairs meet WCAG AA, identical basis to Phase 1/2 verification.

## Screen & Component Contracts

Extends Phase 1 §A/§B (input flow, result screen) and Phase 2 §A–§H (auth, storico, PDF) unchanged. The following are net-new for Phase 3.

### A. Result screen — "Passa a Pro" behavior change (modifies `SoftWallCta.tsx`)

- **Free/anonymous user, not Pro:** clicking "Passa a Pro" now navigates to `/passa-a-pro` (§B) instead of showing the Phase 1 soft-wall toast. "Contatta un professionista" remains soft-wall/deferred (Phase 4) — unchanged.
- **Pro user:** the "Passa a Pro" button is replaced by a **"Vedi dettaglio Pro"** button (accent, same slot/position) that navigates to the detail screen (§C). The four category cards on the result screen gain a per-card **"Vedi dettaglio"** text-link (Label size, accent) in the `CardHeader`, which also routes to §C anchored to that category — same destination as the CTA cluster button, just an additional entry point directly on the relevant `CategoryCard`.
- **Free user viewing the result screen:** each `CategoryCard` additionally renders the **locked teaser** (§color "Locked/paywall teaser tone") as a compact strip inside the card, below the range figure: lock icon + "Dettaglio disponibile con Pro" (Label) + "Passa a Pro" accent link. This is inline, not a full accordion — it previews the value without any real data, and it is the only place the paywall messaging appears on the result screen (avoids repeating it in the CTA cluster and inside the card).

### B. Upgrade / payment-stub screen (`/passa-a-pro`)

Single centered card, `max-width: 480px`, same page chrome as auth screens (slate-50 background, `xl` vertical rhythm). Layout top to bottom:

1. Heading (Heading size): "Passa a Pro".
2. Subheading (Body, muted): value-prop copy from the table above.
3. Value bullets — 3 rows, each a small `CheckCircle`/`Check` lucide icon (muted, not accent — the icon is decorative confirmation, not a CTA) + Body text, one bullet per line from the copy table.
4. Price placeholder block (secondary surface, `md` padding): the price-placeholder copy, Body muted — explicitly not a real price, per D-07.
5. Primary CTA (accent, full-width, 44px min-height): "Attiva Pro". On click: loading state (disabled, spinner, "Attivazione in corso…", same visual pattern as `PdfDownloadButton`'s loading state) → success: inline confirmation "Il tuo account è ora Pro. Il dettaglio è sbloccato." (Body, below the button, `role="status"`) + auto-redirect (or a manual "Vedi il dettaglio" secondary link) to the result/detail screen → failure: destructive inline text below the button, button re-enabled, no page-level alert (mirrors `PdfDownloadButton` error contract).
6. If the user is **anonymous** (not logged in) and reaches this screen, the primary CTA instead reads the Phase 2 pattern: route to `/registrati?intent=pro` first (reuse the save-at-signup router-state mechanism, D-07/save-at-signup precedent), then resume the stub activation after account creation — no new copy needed beyond what Phase 2 already defines for the registration screen; the "Crea account e salva la stima" heading variant pattern extends analogously if the planner wires an intent-specific heading (discretionary, non-blocking).
7. If the user is **already Pro**, this screen is not reachable via normal navigation (CTA changes to "Vedi dettaglio Pro" per §A) — if reached directly by URL, show a neutral state: "Sei già Pro." (Body) + a single CTA "Vedi dettaglio Pro" (accent) linking to §C.

### C. Pro detail screen (`/dettaglio-pro` or embedded section on the result screen — planner's routing choice; visual contract identical either way)

Centered column, `max-width: 640px` (matches result screen). Server-side paywall (D-08) means this screen only renders real data for Pro accounts; Free accounts hitting the route directly are redirected to §B (never shown partial/leaked data client-side).

1. Heading: "Dettaglio Pro" + intro copy (Body, muted) from the table above — sets the non-reconciliation expectation (D-01) explicitly in the UI, not just in internal docs.
2. **Targeted questions block** (shown once per calculation, above the detail — collapsible/dismissible via the skip link): a `card` (secondary surface, `lg` padding) titled "Qualche dettaglio in più" with up to 3 numeric fields (bagni, porte, condizionatori — from D-04/CONTEXT specifics), each an `input` with `inputmode="numeric"`, min 0, label per copy table, and an amber-toned helper note (Body, small) explaining the default-if-skipped behavior. Primary CTA "Calcola il dettaglio" (accent, 44px) triggers/refreshes the detail below; "Salta, usa la stima automatica" (neutral text link) computes immediately with presets. This block collapses to a compact summary row ("Bagni: 2 · Porte: 5 · Climatizzatori: 1 — Modifica") once answered, to avoid re-asking on every view of an already-saved snapshot's Pro detail.
3. **Detail body — two families, both reuse the `accordion` component, one per category:**
   - **A-EDILE (hierarchical family):** one `accordion` item per sottocategoria (A.1 Demolizioni…, A.2 Massetti…, etc. — Label size trigger, e.g. "A.1 · Demolizioni, rimozioni, trasporto"). Expanded content is a simple row list (not a data-table component — plain flex rows, `sm` gap, `xs` vertical padding each): each **voce** renders as `descrizione` (Body, left) · `quantità stimata + UM` (Body muted, tabular-nums, center-right) · `range prezzo` (Label, tabular-nums, right-aligned) on one row (wraps to two lines on mobile: description full-width, quantity+range on the second line). No accent color on any row.
   - **B-FINITURE / C-SERRAMENTI / D-PRODOTTI (flat catalog family):** same `accordion` shell, but the accordion item is the catalog group heading (e.g. "Pavimenti e rivestimenti") instead of a coded sottocategoria; expanded content is the same voce-row layout. Copy neutrally frames this as "prodotto/materiale" rather than "lavorazione" only if the executor needs a generic row label — not a hard requirement, the row layout is identical.
   - Each accordion item may optionally show a **sottocategoria subtotal** (Heading size, tabular-nums, right-aligned in the trigger row) — allowed but not required; if shown, it must still be a range (`€ min – € max`), never a single number (D-11).
4. **CTA cluster** (bottom, same shell as Phase 1 §B.5): primary "Scarica PDF dettagliato" (accent, `PdfDownloadButton`-pattern reused with the new label) + "Torna alla stima" (neutral/outline, back to the result screen).

### D. States (additions to Phase 1/2 state tables)

| State | Treatment |
|-------|-----------|
| Detail loading (calculating quantities) | `skeleton` rows matching the accordion-item height (one skeleton bar per expected sottocategoria) — same pattern as Phase 1's 4-card skeleton, just more rows. |
| Detail error (calc failed) | `alert` (destructive tone) with the "Non siamo riusciti a calcolare il dettaglio…" copy + "Riprova" button, same pattern as Phase 1 §C. |
| Locked (Free user, direct URL to detail) | Redirect to `/passa-a-pro` (§B) — no partial UI is ever rendered client-side for a non-Pro account (server-side gate, D-08); this is a navigation state, not a visible "locked" screen variant. |
| Locked teaser (Free user, on result screen cards) | Inline strip per §A, third bullet — visible, not a redirect (this is the marketing surface; the redirect only applies to the actual detail route). |
| Payment-stub activating | Button loading state per §B.5. |
| Payment-stub success | Inline confirmation + redirect per §B.5. |
| Payment-stub error | Inline destructive text per §B.5, no full-page alert. |
| Targeted questions — skipped | Detail computes immediately with mq/tipo-based presets; the collapsed summary row (§C.2) shows "stima automatica" instead of counts. |
| PDF Pro generating/error | Identical to Phase 2 §F.4/§G (`PdfDownloadButton` pattern), only the default label text changes to "Scarica PDF dettagliato" for Pro accounts. |
| Accordion — empty sottocategoria | Render the item but with the "Nessuna voce stimata…" copy in place of rows (Body, muted, centered) — never hide the sottocategoria entirely, keeps the hierarchy legible. |

### E. PDF Pro document branding (PDF-02, extends Phase 2 §H)

Same palette/header/footer contract as the Phase 2 Free PDF (§H) — Slate/blue-600, wordmark + name + date header, legal footer line, filename pattern `stima-ristrutturazione-<citta>-<data>.pdf` (Pro variant may append `-dettaglio` before the extension, e.g. `stima-ristrutturazione-reggio-emilia-2026-08-26-dettaglio.pdf`, executor's choice, non-blocking). **Net-new for the Pro document:**
- Multi-page allowed (unlike the Free 1-pager) — one section per category, each listing its sottocategorie/gruppi and voci in a compact table (print-optimized: `descrizione` | `UM` | `quantità stimata` | `range prezzo`, right-aligned numeric columns, tabular figures, thin slate-200 row dividers, no zebra-striping needed to stay consistent with the flat web-app row style).
- A short intro paragraph on page 1 carrying the same non-reconciliation disclaimer as §C.1 ("Questo dettaglio è una stima indipendente, più precisa del totale rapido…"), in Body size, so a printed Pro PDF is self-explanatory even without the web context.
- Domain guard (binding, unchanged from Phase 1/2): the Pro PDF template must never render `coefficiente_impresa`, `base_eur_mq`, moltiplicatori, or `prezzo_impresa` — only client range values already permitted in the API. Re-verify with the same anti-leak test pattern (`test_no_leak.py`) extended to the Pro detail payload and PDF.

## Open Questions (non-blocking — reasonable defaults/assumptions set above)

1. **Detail screen routing (`/dettaglio-pro` dedicated route vs. an expanded in-place section on the result screen)** — left to the planner/executor per CONTEXT.md discretion ("accordion per sottocategoria vs tabella" was explicitly deferred). This spec defaults to a **dedicated route** for shareability/back-button and to keep the anti-leak-tested result screen minimally touched, but the visual contract (§C) applies identically if implemented as an in-place expansion instead.
2. **Targeted-question set (bagni/porte/condizionatori)** — proposed here as the 3 highest-impact counts per D-04's own examples; CONTEXT.md explicitly defers the *exact* set and coefficients to research/planning + Fase 4 admin tuning. Not blocking: the visual contract (a small card with N numeric fields + skip link) holds regardless of the exact final set or count of questions (even if the planner lands on 2 or 4 fields).
3. **Sottocategoria subtotal display** — marked optional in §C.3; if the planner/executor omits it, no contract is violated (only voce-level ranges are mandatory).
4. **PDF Pro pagination/print-table library** — WeasyPrint (already in use, Phase 2 decision) is assumed to handle a longer multi-page document via standard CSS `@page`/table break rules; no new PDF technology introduced.
5. **Upgrade-screen anonymous-user routing detail (§B.6)** — the exact wiring of `intent=pro` through `/registrati` is a reasonable extrapolation of the existing Phase 2 save-at-signup router-state mechanism, not a new pattern; planner may implement equivalently.
